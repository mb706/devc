**Deviations and choices.**

1. `./dev itest` always rebuilds `bin/devc` and `bin/itest` (the work order says build if missing): a stale binary would silently test old code, and the build cache makes it cheap. It translates `go test` flags (`-v`, `-run X`) to test-binary flags and runs from `test/integration`. Added `./dev go …` as a passthrough; `./dev vet` includes `-tags integration`; `./dev test` passes extra flags to `go test` and adds `./...` when no package is named.
2. Session IDs use lower-case base32hex (`0-9a-v`), because only that alphabet sorts lexically in numeric order: 50-bit millisecond time plus 50 random bits, strictly increasing within a process.
3. `config show` without an argument prints the global view (effective directories, engine, box defaults, hubs); it does not infer a project from the working directory, so its output schema does not depend on where it runs. With an argument it accepts `realm/project` or a unique bare name.
4. Read-only commands (`ls`, `show`, `doctor`) run despite configuration problems and print a one-line warning. `Config.ProblemsFor(ref)` returns the problems affecting one project (global, realm, project, its env, its manifests) so lifecycle commands from C02 on can refuse to act. Files with syntax or type errors drop their entity; unknown keys are reported but keep it. A realm directory without `realm.toml` (or a project directory without `project.toml`) is a problem and is skipped. `config check` fails if the config directory does not exist.
5. State directory precedence: `--state-dir` > `DEVC_STATE_DIR` > `state_dir` in `config.toml` > default. `projects_root` and `state_dir` must be absolute or start with `~/`.
6. Validation beyond the work order, all for argument safety or obvious mistakes: `upstream` refuses `<transport>::` URLs (`ext::` runs commands) and unknown schemes; image references, SSH aliases, branch names and globs cannot start with `-`; data paths have no component starting with `-`; `data.root` is one name (name rules) other than `main`; harness `bin` values are unique and not `devc`, `devc-*` or `git-remote-devc` (argv[0] dispatch); a user manifest's file name must equal its `id`; a realm override to `env-token`/`api-key` needs `auth.env` in the manifest; `home.shared` only with `private`, `home.per_box` only with `shared`; `launch.resume` must contain `{id}`; duplicates in harnesses, grants, ports, mounts and zones are errors.
7. Types and defaults not fixed by the work order: `box.ports` is a list of integers; `[[mounts]] mode` defaults to `ro`; `savepoints.keep = 0` means keep all; project `box.pids = 0` inherits; manifest defaults are `install.method = "none"`, `auth.method = "none"`, `home.strategy = "private"`, `input.adapter = "paste"`, `submit_key = "Enter"`, `seed.when = "missing"`, `display = id`.
8. `paths` getters panic on a name that did not pass `names` (a programming error, never user input), rather than returning errors from every getter.
9. `execx.Interactive` has no default timeout (attached sessions last hours); `Run` defaults to 2 minutes, sends SIGTERM on timeout and SIGKILL 5 s later. The fake picks the longest matching prefix, the latest registration among equals.
10. Doctor details: `subids` also accepts the engine's actual ID mapping (covers subordinate IDs from LDAP/sssd); `cgroups` reads delegated controllers from `podman info` when rootless, else from `user@<uid>.service`; `linger` falls back to `/var/lib/systemd/linger/<user>`; "distribution path" for AppArmor means a profile in `/etc/apparmor.d` that attaches to the resolved engine binary and grants `userns`; `projects-fs` probes the nearest existing ancestor when the projects root does not exist yet (and says so); a missing `ssh` is a warning; `vfs` storage and CNI also warn; SELinux permissive counts as enabled.

**Deviations and choices.**

1. **Extra creation flags.** `podman create` has no `--passwd=false` (only `run` does), so boxes get `--passwd-entry` as in spec 6.2; it covers the moment before `fix-identity`, which then makes the files canonical (Podman adds nothing once UID 1000 exists). `--http-proxy=false`: the host's proxy variables are host environment, not policy, and may carry credentials. Engine-default network levels pass no `--network` at all.
2. **Seccomp beyond the work order.** The kernel truncates the socket domain to 32 bits while seccomp compares 64, so `socket(0x100000026, …)` creates an AF_ALG socket under the base profile (verified here). Every allow range therefore requires the upper 32 bits to be zero (aligned power-of-two blocks with `SCMP_CMP_MASKED_EQ`, about 70 rules), and the AF_ALG refusal matches the low 32 bits. The no-`CAP_AUDIT_WRITE` ranges also exclude 40, which removes the base profile's overlap of "allow domain != 16" with "refuse domain == 40". No rule overlaps another with a different action, so nothing depends on libseccomp's tie-breaking.
3. **Hash inputs** include the seccomp digest (the engine reads the profile only at creation), so a devc upgrade that changes the profile shows as drift.
4. **`up --recreate`** always recreates; `rebuild` builds the env (if it has a Containerfile) and recreates; image projects are not re-pulled. On an already running box, `sh`, `run` and `root` exec even if it has drifted; a stopped box is started through `up`, so drift stops them.
5. **Fail-closed scope.** `down`, `rm` and `ls` still work with configuration problems (they only stop or remove, or read); all commands that create, start or exec refuse.
6. **Nested mount points.** Before every create/start, each mount that lies inside another mount (today `/home/dev/.cache` in the home) must be a real directory at that place in the parent's host source; a symlink planted by the box (for example `.cache -> /opt/devc`) would otherwise redirect the mount inside the box and shadow the toolbox. Missing mount points are created; anything else is refused.
7. **`devc box shell`** (not in the work order) chooses the shell inside the box (`box.shell` from `box.json`, else zsh, bash, sh in `/bin`, `/usr/bin`, `/usr/local/bin`) and execs it as a login shell; `devc sh` runs it with `-i` and `-t` only when stdin is a terminal. All `devc box` commands refuse unless `DEVC_BOX=1` and `/etc/devc/box.json` exist, so `fix-identity` can never rewrite a host's `/etc/passwd`.
8. **`fix-identity`** replaces entries matching UID/GID 1000 or the name `dev` (and 2000/`vault`) with canonical lines at the position of the first match, keeps a replaced group's member list, keeps every other line byte for byte, writes by rename (falling back to in-place on `EBUSY`/`EXDEV`), and leaves `/etc/shadow` alone. `vault` has home `/nonexistent` and a nologin shell.
9. **`box init` and dotfiles.** Dotfile links replace existing symlinks and skip real files; links to removed dotfiles are deleted. The host copies only regular files and directories from `<config>/dotfiles/` (symlinks and special files are skipped with a log line, `.git` is skipped), so a symlink in the dotfiles repository cannot copy an arbitrary host file into a box.
10. **`box selftest`** items: identity, capabilities (CapEff), no-new-privileges, `unshare(CLONE_NEWUSER)` and `clone(CLONE_NEWUSER|CLONE_FS)` must fail with ENOSYS (the kernel alone would say EINVAL, so ENOSYS proves the seccomp rule), `clone3` ENOSYS, AF_ALG EAFNOSUPPORT with and without upper bits, ordinary sockets still work, `/opt/devc` and `/etc/devc` read-only, project directory writable. Under the unmodified base profile all six seccomp items fail.
11. **Integration-test naming** deviates from README ("containers named `devc-it-…`, labelled `devc.test=1`"): box names and labels are fixed by the plan, so the harness renames the copied example configuration instead: realms `itdemo`/`itother`, env `itbase` (boxes `devc-itdemo-hello` etc.). Containers labelled with these realms are removed before and after every test; `localhost/devc-env/it*` images are removed at the end of the run, pulled Debian images only if they were absent at the start.
12. **Host bug worked around in tests.** On this host, `statx()` asking for the birth time on a file in an image layer hangs forever in fuse-overlayfs 1.17 with libfuse 3.18.2 (the process sits in `request_wait_answer`). Debian trixie's `apt-get update` verifies signatures with `sqv`, which does exactly that, so the example `base` env cannot be built here; `stat FILE` hangs too, while `ls -l` and `stat -c %s` work. The test harness builds the base env from `debian:bookworm-slim` (apt uses gpgv); the example configuration stays on trixie. Not a devc problem; see LEFTOVER.
13. **AppArmor.** Nothing box-specific: rootless Podman applies no AppArmor profile (`podman info` reports it disabled), and devc never passes `apparmor=…`. The host-side user-namespace restriction remains a `doctor` check (unchanged; it warns here, as expected).
14. **SELinux.** Mode `labels`: `label=level:<realm level>` when the realm sets one, never `:z`/`:Z`, and `restorecon -R -- <project dir>` (from `/`) during `up` when the tool exists, otherwise a warning. Mode `disable`: `label=disable` plus a one-line warning. Both only when `/sys/fs/selinux/enforce` exists; tested with fakes only.

**Deviations and choices.**

1. **socketcall gets EPERM, not ENOSYS.** runc drops rules whose action equals the default (ERRNO ENOSYS). Without an explicit unconditional socketcall rule, libseccomp rewrites every `socket` rule on the x86 sub-architecture into a socketcall rule (the domain comparison replaced by the call number), and rules with different actions then collide: containers fail with "error adding seccomp rule for syscall socket: file exists" (verified). An explicit EPERM rule placed before the socket rules makes those rewritten rules redundant. Consequence: 32-bit programs that use socketcall (32-bit glibc does) have no sockets at all; a libc using the direct calls is unaffected and meets the AF_ALG rule. The derivation fails if a future base profile's default is EPERM.
2. **Secrets mount at `/run/devc-secrets`** (work order) instead of `/run/devc/secrets` (plan 3.10): `/run/devc` is box-writable, and a mount nested in it could be redirected by a planted symlink.
3. **Session ID reuse.** `DEVC_SESSION` is kept only when valid and `DEVC_HARNESS` is unset; a harness started from inside another harness's session gets a new ID instead of sharing its parent's.
4. **Method `none`** counts as installed when `install.exe` is set; `harness install` only creates the shim; without `exe` the manifest loads but `up` warns. Validation: `local` needs `path` (absolute or `~/`), `exe` relative; `script` URL must be https without user info; baseline settings and instructions must share one dedicated directory (at least two levels deep, not under `/etc/devc`, `/opt/devc`, `/home`, `/w`, `/ctx`, `/run`, `/usr`, …), because that directory is mounted over the image.
5. **Installer details.** Containers from the installer image get empty tmpfs mounts at `/home`, `/opt` and `/tmp`, so the directories above devc's bind mounts are not image-layer directories. On this host that is also required: Claude Code's installer (Bun) `lstat`s every component of its target path with the birth-time mask, and `statx("/opt")` on the image layer hung in fuse-overlayfs exactly as in C02. `{version}`: an argument containing it is dropped when no version is requested; `--version` is refused for `local`. The installer container runs as container root (the host user) with podman's default capabilities and the host proxy variables (podman's default; boxes keep `--http-proxy=false`), so vendor installers that untar as root work. The check container gets `HOME=/tmp` and no network. `harness gc` keeps the union of current and the two newest directories (two when current is the newest).
6. **Templates** for seeds and settings come from `<config>/harness/<name>` for user manifests, else from the embedded `assets/harness/templates/`; `sandbox.md.tmpl` may be overridden the same way. Template functions: `json`, `toml`, `join`, `hook`.
7. **Logins** run as container root with a temporary home at `/home/dev` (below `local/tmp/`, removed afterwards), the toolbox read-only and network on; a login command whose first word is the harness's `bin` runs the real executable. `shared-home` mounts the realm's `harness/<id>/home` at the harness home. `--token-stdin` is refused for `shared-home`; `api-key` prompts (or reads stdin). Granted secrets are exported only when their name is a valid environment variable name; others are files only.
8. **Hidden prompts** use termios from `golang.org/x/sys` (echo off, restored on SIGINT) rather than adding `golang.org/x/term`.
9. **Integration-test caches.** The installer image stays between runs; the tmux build is cached in `${DEVC_DEV_CACHE:-~/.cache/devc-dev}/itest/tmux-<version>-<recipe>/` and copied into each test toolbox (`DEVC_TEST_REBUILD_TMUX=1` forces a build). `alpine:3.24.4` is in the list of pulled images removed at the end when it was absent at the start. `./dev itest` passes `DEVC_FAKEAGENT` and `DEVC_ITEST_CACHE`.

**Optional network test** (`DEVC_TEST_NETWORK_HARNESS=1`, run once by hand). ### C03r Fixes after review A

All 21 findings of `docs/dev/reviews/A-review.md` are addressed; `docs/dev/reviews/A-response.md` has one paragraph per finding. Summary of what changed:

- **Box lifecycle** (`internal/box`). `up` decides from the existing container first (no-op, finish a start, drift refusal, recreate) and writes `/etc/devc`, baselines, launch descriptions, secrets, mount sources and mount points only on a path that creates or starts the box. A failed create/start is rolled back (created container removed, started container stopped, secrets removed). A running box without the readiness marker is not "already running": `up`, `sh`, `run` and `root` finish its start. Every lifecycle operation holds `local/boxes/<r>/<p>/lock` (new package `internal/flock`, bounded wait of 10 minutes). Root execs (`devc root`, `fix-identity`) run with `PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`, `HOME=/root` and working directory `/`. `rm --home` empties the home in the helper container (`devc box rm-worker`, `--rootfs <toolbox>/helper-rootfs:O`, network none, only `DAC_OVERRIDE`/`FOWNER`) and then removes the empty directory.
- **Box arguments.** `--entrypoint /opt/devc/bin/devc` with command `box init`; `TERMINFO_DIRS=/opt/devc/terminfo:` (the trailing empty entry keeps the image's database; verified on bookworm, whose ncurses searches its compiled-in directories anyway); `gpu` → `--device nvidia.com/gpu=all`, `kvm` → `--device /dev/kvm --group-add keep-groups`, `nested` refused. A configured memory or PID limit whose controller is not delegated fails `up`; `memory = "none"` and `pids = -1` switch a limit off (global `pids = 0` is now a problem). The arguments changed, so every box created before C03r shows as drifted once (`devc up --recreate`).
- **Network.** `internet` and `allowlist` are refused until C07; only `none` and `open` create boxes. **The example realm `demo` sets `network.default = "open"` explicitly for now; C07 must switch it back to `internet`.** The default for a realm without the key stays `internet` (refused). The sandbox description only describes levels in force.
- **Filesystem.** `safefs.Root.MkdirAll`/`RequireDirs` (mkdirat plus openat2 without symlinks, per component); `paths.Ensure` and the new `paths.EnsureBeneath` (projects root) use them, as does the mount-point preparation. Manifests whose `home.shared`/`home.per_box` entries nest are refused, and so are projects whose harness homes overlap.
- **Configuration.** A user manifest that exists but fails to load (or a manifest directory that cannot be listed) blocks every project using that id; the built-in manifest is never used instead (`Config.HarnessProblems`). `auth.method = "shared-home"` requires `home.strategy = "shared"` (manifests and realm overrides). Manifests gained `baseline.files` (template-only files in the baseline directory) and `baseline.settings.also` (more paths for the same settings).
- **Codex baseline.** `/etc/codex/requirements.toml` (allowed approval policy `never`, sandbox mode `danger-full-access`, `[features] hooks = true`, the five managed hooks) plus the settings in both `/etc/codex/config.toml` and `/etc/codex/managed_config.toml`; hooks are no longer in `config.toml`. `CODEX_RELEASE = "{version}"` passes `--version`; `{version}` works in `install.env`; `--version` is refused for manifests without the placeholder.
- **Harness installs** (`internal/toolbox`). Publication writes `installed.json` first and switches `current` last under a short publish lock (readers take it shared), restoring the old metadata on failure; switches are logged in `harness/<id>/history.jsonl`. Launch descriptions name the concrete version directory; `devc update` and `harness install` rewrite the descriptions of all boxes that have one (running boxes start the new version at the next launch). `harness gc` keeps current, the two newest, every version a description names and every version current since the oldest running box started; it refuses to remove anything when it cannot list the running boxes.
- **Secrets.** Delivery fails unless the secrets directory is on tmpfs or ramfs, or `DEVC_ALLOW_PERSISTENT_SECRETS=1`.
- **Containers.** Every auxiliary container and every image build runs with `--http-proxy=false` (C03 deviation 5 is reversed). `execx` runs every command from `/` unless a directory is given.
- **Integration tests.** Each run draws a nonce: realms `itdemo<nonce>`/`itother<nonce>`, envs `itbase<nonce>`/`ituid<nonce>`. devc honours `DEVC_TEST_RUN=<nonce>` by labelling every container and image it creates with `devc.test=1` and `devc.test.run=<nonce>` (outside the box definition, so the hash is unchanged); cleanup removes exactly what carries the run's label (the shared installer image excepted). Runtime directories live below `$XDG_RUNTIME_DIR`.

**Deviations from the work order.**

1. **socketcall stays EPERM.** Removing `socketcall` from the allow lists (as ordered) was tried: every container fails with "error adding seccomp rule for syscall socket: file exists" under runc, as C03 had found. An explicit ENOSYS rule is dropped by runc (equal to the default action) and `SCMP_ACT_TRACE` (ENOSYS without a tracer) could be bypassed by a tracer in the box. The C03 rule and self-test are unchanged; the reasons are in `internal/toolbox/seccomp.go`.
2. **`harness install` also rewrites launch descriptions**, not only `devc update` (E1): otherwise a new installation would no longer reach running boxes at their next launch, as it did through `current` before.
3. **Running-but-not-ready boxes** that this invocation did not start are not stopped when finishing their start fails; `up` reports the error and says to run `down` and `up`. Rollback only undoes what the invocation itself did.
4. **`up` on a running box writes nothing** (consequence of A3): to deliver a new secret or baseline to a running box, restart it.
5. **Test-run labels in production code.** `DEVC_TEST_RUN` is read by the CLI (`app.engine`) and only adds labels; it is the mechanism D1 needed for "every object carries a label with that run's nonce".
