**Deviations and choices.**

Added `./dev go …` as a passthrough; `./dev vet` includes `-tags integration`; `./dev test` passes extra flags to `go test` and adds `./...` when no package is named.
2. Session IDs use lower-case base32hex (`0-9a-v`), because only that alphabet sorts lexically in numeric order: 50-bit millisecond time plus 50 random bits, strictly increasing within a process.
3. `config show` without an argument prints the global view (effective directories, engine, box defaults, hubs); it does not infer a project from the working directory, so its output schema does not depend on where it runs. With an argument it accepts `realm/project` or a unique bare name.
4. Files with syntax or type errors drop their entity; unknown keys are reported but keep it. A realm directory without `realm.toml` (or a project directory without `project.toml`) is a problem and is skipped. `config check` fails if the config directory does not exist.
5. State directory precedence: `--state-dir` > `DEVC_STATE_DIR` > `state_dir` in `config.toml` > default. `projects_root` and `state_dir` must be absolute or start with `~/`.

**Deviations and choices.**

1. **Extra creation flags.** `podman create` has no `--passwd=false` (only `run` does), so boxes get `--passwd-entry` as in spec 6.2; it covers the moment before `fix-identity`, which then makes the files canonical (Podman adds nothing once UID 1000 exists). `--http-proxy=false`: the host's proxy variables are host environment, not policy, and may carry credentials. Engine-default network levels pass no `--network` at all.
2. **Seccomp beyond the work order.** The kernel truncates the socket domain to 32 bits while seccomp compares 64, so `socket(0x100000026, …)` creates an AF_ALG socket under the base profile (verified here). Every allow range therefore requires the upper 32 bits to be zero (aligned power-of-two blocks with `SCMP_CMP_MASKED_EQ`, about 70 rules), and the AF_ALG refusal matches the low 32 bits. The no-`CAP_AUDIT_WRITE` ranges also exclude 40, which removes the base profile's overlap of "allow domain != 16" with "refuse domain == 40". No rule overlaps another with a different action, so nothing depends on libseccomp's tie-breaking.
3. **Hash inputs** include the seccomp digest (the engine reads the profile only at creation), so a devc upgrade that changes the profile shows as drift.
4. **`up --recreate`** always recreates; `rebuild` builds the env (if it has a Containerfile) and recreates; image projects are not re-pulled. On an already running box, `sh`, `run` and `root` exec even if it has drifted; a stopped box is started through `up`, so drift stops them.
5. **Fail-closed scope.** `down`, `rm` and `ls` still work with configuration problems (they only stop or remove, or read); all commands that create, start or exec refuse.
6. **Nested mount points.** Before every create/start, each mount that lies inside another mount (today `/home/dev/.cache` in the home) must be a real directory at that place in the parent's host source; a symlink planted by the box (for example `.cache -> /opt/devc`) would otherwise redirect the mount inside the box and shadow the toolbox. Missing mount points are created; anything else is refused.
7. **`devc box shell`** (not in the work order) chooses the shell inside the box (`box.shell` from `box.json`, else zsh, bash, sh in `/bin`, `/usr/bin`, `/usr/local/bin`) and execs it as a login shell; `devc sh` runs it with `-i` and `-t` only when stdin is a terminal. All `devc box` commands refuse unless `DEVC_BOX=1` and `/etc/devc/box.json` exist, so `fix-identity` can never rewrite a host's `/etc/passwd`.
8. **`fix-identity`** replaces entries matching UID/GID 1000 or the name `dev` (and 2000/`vault`) with canonical lines at the position of the first match, keeps a replaced group's member list, keeps every other line byte for byte, writes by rename (falling back to in-place on `EBUSY`/`EXDEV`), and leaves `/etc/shadow` alone. `vault` has home `/nonexistent` and a nologin shell.
9. **`box init` and dotfiles.** Dotfile links replace existing symlinks and skip real files; links to removed dotfiles are deleted. The host copies only regular files and directories from `<config>/dotfiles/` (symlinks and special files are skipped with a log line, `.git` is skipped), so a symlink in the dotfiles repository cannot copy an arbitrary host file into a box.
10. **`box selftest`** items: identity, capabilities (CapEff), no-new-privileges, `unshare(CLONE_NEWUSER)` and `clone(CLONE_NEWUSER|CLONE_FS)` must fail with ENOSYS (the kernel alone would say EINVAL, so ENOSYS proves the seccomp rule), `clone3` ENOSYS, AF_ALG EAFNOSUPPORT with and without upper bits, ordinary sockets still work, `/opt/devc` and `/etc/devc` read-only, project directory writable. Under the unmodified base profile all six seccomp items fail.
11. **Integration-test naming** deviates from README ("containers named `devc-it-…`, labelled `devc.test=1`"): box names and labels are fixed by the plan, so the harness renames the copied example configuration instead: realms `itdemo`/`itother`, env `itbase` (boxes `devc-itdemo-hello` etc.). Containers labelled with these realms are removed before and after every test; `localhost/devc-env/it*` images are removed at the end of the run, pulled Debian images only if they were absent at the start.

The test harness builds the base env from `debian:bookworm-slim` (apt uses gpgv); the example configuration stays on trixie. Not a devc problem; see LEFTOVER.

**Deviations and choices.**

1. **socketcall gets EPERM, not ENOSYS.** runc drops rules whose action equals the default (ERRNO ENOSYS). Without an explicit unconditional socketcall rule, libseccomp rewrites every `socket` rule on the x86 sub-architecture into a socketcall rule (the domain comparison replaced by the call number), and rules with different actions then collide: containers fail with "error adding seccomp rule for syscall socket: file exists" (verified). An explicit EPERM rule placed before the socket rules makes those rewritten rules redundant. Consequence: 32-bit programs that use socketcall (32-bit glibc does) have no sockets at all; a libc using the direct calls is unaffected and meets the AF_ALG rule. The derivation fails if a future base profile's default is EPERM.
2. **Secrets mount at `/run/devc-secrets`** (work order) instead of `/run/devc/secrets` (plan 3.10): `/run/devc` is box-writable, and a mount nested in it could be redirected by a planted symlink.

The launcher's `registerSession` writes `session.start` (harness, worktree from `DEVC_WORKTREE` or the working directory, cwd, PID). `AppendEvents` validates every event as the host would and appends all lines in one `O_APPEND|O_NOFOLLOW` write.

**Deviations and choices.**

1. **Window command.** The window runs `/opt/devc/bin/devc box launch <id> -- args…` instead of the shim path: tmux runs a one-argument command through `sh -c`, and only an argument vector of two or more is executed directly. It does exactly what the shim does.
2. **End of a pane.** `pane-exited` fires after the pane is gone, so its exit status is lost; devc sets `remain-on-exit on` and uses `pane-died`, whose `run-shell` sees `#{pane_dead_status}`/`#{pane_dead_signal}`, and the helper removes the dead pane afterwards. Both are set globally in `tmux.conf` (before `~/.tmux.conf`) and again per window. A harness that exits before its window is tagged (milliseconds) gets no `session.end` from tmux; reconciliation marks it `lost`. tmux turns tabs in format output into `_`, so `list-panes` output is space-separated with the box-controlled session option last.
3. **Start and attach.** `devc <harness>` without `--detach` is one interactive `podman exec -it --detach-keys= -e TERM -e COLORTERM -e TERMINFO_DIRS=…` of `box session start`, which creates the window and then execs the tmux client; with stdin not a terminal it starts detached and says so. The client's grouped session is targeted as `=devc-<hex>:` (with the colon; `set-option` resolves a bare name as a pane or window first). `devc attach` refuses without a terminal; with one argument it is a project if it names one, else a session prefix searched in every project; prefixes may omit the `s`; "most recent" is the highest session ID.
4. **Reasons devc writes for `session.end`:** `exited` (+ status), `killed` (+ signal), `stopped` (`devc stop`), `lost` (reconciliation), `box-down`. Ingestion drops every event of a session after its first end (counted, never journaled), which also absorbs the second end when both the harness and the tmux hook write one; that is why `session ended` writes an end even when the spool file is gone.
5. **Reconciliation race.** Refresh ingests, records the sessions open at that point, asks the box, ingests again, and ends only those recorded sessions that the box does not report; a session that starts or ends meanwhile is never marked lost by mistake. Dead panes do not count as alive. A box report that fails strict parsing changes nothing (a warning). A box that is not running ends all open sessions as `lost`; a running box that is not ready is only ingested.
6. **`devc down`/`rm`.** Before the stop: ingest and reconcile (as ordered). After it: ingest again and end every open session with `box-down`, then commit the realm's context. A `down`/`rm` of a box that was not running ends open sessions as `lost` and commits nothing (so no-op downs start no container).
7. **Ingestion bounds and locking.** Per run and file at most 8 MiB and 20,000 events; at most 10,000 spool entries (more fails the run for that box). The offsets file keeps `{offset, discard}` per file; `discard` skips the rest of an oversized line across runs. A separate `local/boxes/<r>/<p>/ingest.lock` serialises ingestion (the box lock can be held for minutes by `up`). Projects with neither journals nor a runtime directory are not touched (`ls` creates no state).
8. **Listing times** are the host's ingestion times (`at`), which a box cannot choose: AGE is since the session's start, the 24-hour window counts from its end. Old ended journals are skipped by mtime plus a last-line check, so `ps` does not parse every journal ever written.
9. **Context repository.** Bare, so git never treats the box-written tree as a work tree. The worker scans with safefs (no symlink followed anywhere), builds the commit with `git fast-import` (`deleteall` plus one `M` line per accepted file, C-quoted paths), and moves `main` only when the tree changed; `diff` compares `main` with such a snapshot (tree to tree, `--no-ext-diff --no-textconv`), `log` is `--stat`. Left out and reported: entries that are git metadata on any filesystem (`.git` in any case, NTFS trailing dots/spaces, `git~1`, HFS-ignored characters) — only the entry, so a planted `.git` cannot hide its siblings; symlinks; special files; unreadable directories; files over 10 MiB. Over 50,000 files or 512 MiB the snapshot is refused rather than committed in part (a partial tree would record deletions). The container runs as its root, which is the host user, without capabilities, so files of subordinate UIDs are unreadable and skipped. Fixed identity `devc <devc@localhost>`.
10. **Terminal safety beyond the work order.** Error messages printed by the CLI pass through `PrintableText` (`execx.ExitError` embeds the first stderr line of a command, which the box controls for in-box execs); JSON output escapes DEL and C1 controls, which `encoding/json` leaves raw.
11. **Harness commands** are registered before flag parsing, so `--config-dir` is pre-scanned from the raw arguments; nothing is registered in a box (`DEVC_BOX=1`, which also keeps devc from reading a box home's `~/.config/devc`), and a manifest `bin` that equals a devc command is skipped.
12. **`devc stop`** of a session started from a shell sends SIGTERM to its processes (there is no window to kill).
13. **Stale boxes.** A box started before C04 has no `tmux.conf`; `box session start` tells the user to restart it. A harness installed after its box started has no launch description in it; the host says so before starting.
14. **Dependency:** `github.com/creack/pty` v1.1.24 (approved list), used by the integration tests only.

**How to exercise.** `./dev build`; with a configuration whose project lists `fake` (or `claude`): `bin/devc toolbox build tmux`, `bin/devc harness install fake`, `bin/devc fake <ref>` (attaches; detach with C-b d), `bin/devc fake <ref> --detach`, `bin/devc ps`, `bin/devc ls`, `bin/devc attach <ref> [session]` from another terminal or `ssh -t <host> devc attach <ref>`, `bin/devc stop <session>`, `bin/devc context diff|commit|log <realm>`, `bin/devc down <ref>`. **Deviations and choices.**

1. **Remote helper and deletions.** The stub reports `ok` for every branch update but answers a deletion (`push :ref`) with `error`, because the relay never deletes a branch; reporting success would make the box drop its tracking ref until the next bank.
2. **Ref names.** devc's limits on top of git's: printable ASCII only, at most 200 bytes, not `HEAD`. Unicode branch names from a box are therefore skipped and reported. `git check-ref-format --branch` runs for every changed branch (in addition to the Go check). A bank applies at most 1000 changed branches and 1000 new tags; the rest wait for the next bank.
3. **Bank details.** A new bank ref is recorded when the tip differs from the branch's newest bank ref (so A→B→A records A again). Timestamps are host seconds; a collision takes the newest existing stamp plus one, so refs never clash and sort in order. Each branch update (head plus bank ref) is its own transaction with the old value as a check, so one refused update (a directory/file conflict such as `x` kept in the relay and `x/y` in the box) does not stop the others. Snapshots count as "differing" when tree or parents differ; the box also reuses its own `refs/devc/wip/<worktree>` commit when nothing changed, and deletes it when the worktree is clean. Tags equal to the relay's `refs/tags` (handed in from the upstream) are not recorded as box tags. Untracked files are skipped when over 10 MiB, nested repositories and special files are skipped too; all are listed in the commit message and the summary (not with `--quiet`). `--quiet` prints refused refs, failures and forward failures. `devc bank <ref>` on a stopped box prints a note and exits 0; `bank --all` waits at most a minute for a busy box and exits 1 only when a bank failed.
4. **Pull.** Relay branches ahead of the upstream are left alone silently; only true divergence is reported. Deleted upstream branches are pruned from `refs/remotes/github/*`, tags are not. On a stopped box the relay is updated and a note says the box gets the refs later. Tags are pushed into the box without force; a box tag of the same name is kept and reported.
5. **Push.** The first argument is the project when it names a configured project, otherwise all arguments are branches. Without branches and tags it pushes the branch checked out in `main` (the relay's HEAD when the box is not running). It pushes the tip object that was previewed (not the ref name), with `--force-with-lease=<ref>:<last fetched tip>` whenever `--force` is given. Without a terminal it needs `--yes`. `--tag` alone pushes only the tag.
6. **Matching repository.** `project init` treats an existing box repository as matching when `.repo` is a repository whose `remote.origin.url` is `devc::<realm>/<project>`; anything else (another origin, an invalid `.repo`, a `main/.git` without `.repo`) is refused. On a match it re-applies the box configuration, reflects all refs and checks out the default branch only if nothing is checked out. Checkout uses `git checkout -b <b> --track origin/<b>`, which refuses to overwrite untracked files rather than resetting.
7. **Adopt.** The upstream defaults to the clone's `remote.origin.url`, read with `git config --file <clone>/.git/config` (one file, no includes, nothing runs); a URL devc would refuse is dropped with a warning. Local branches enter the relay with bank refs, `origin/*` (except `origin/HEAD`) become `refs/remotes/github/*`, tags `refs/tags/*`; then relay branches are created from the upstream refs as in `init`. Default branch: `default_branch`, else the clone's `origin/HEAD` target, else its checked-out branch, else `main` (no network needed). Clones inside the projects root or the state directory are refused (they are box-writable).
8. **`-w` without a relay.** `devc <harness> -w <name>` creates the worktree only for projects that have a relay; projects never initialised keep C04's behaviour (the session starts in the project directory). C04's session tests rely on that.
9. **Realms.** `realm add` writes the network level only when `--network` is given; the default (`internet`) is refused until C07, so new realms for now need `--network open` or `none`.
10. **Log and diff output** is captured, control characters other than git's own colour sequences are replaced (commit messages and file contents are box-written), and the result is paged through `$GIT_PAGER`, `$PAGER` or `less` (with `LESS=FRX` unless set) when stdout is a terminal. `--ext-diff` and `--textconv` are refused in user arguments. Log and diff take no lock (read-only).
11. **Service.** The units carry the current `PATH` and, when set by flag or environment, `DEVC_CONFIG_DIR`, `DEVC_STATE_DIR` and `DEVC_RUNTIME_DIR`; `DEVC_SYSTEMD_USER_DIR` overrides the unit directory (for tests). `context commit --all` (new flag) commits every realm that has a context directory and prints only commits and problems.
12. **Extra in-box commands** beyond plan 3.3's table: `box worktree …`, `box worktree-hook …`, `box repo-state`. `execx.Cmd` gained `Unset` (variables removed from the inherited environment).

**What exists.**

Projects without `[data]` are untouched (no worker, no `.devc`).
- **Helper workers** (`internal/boxside`: `datalayout.go`, `dataproto.go`, `dataworker.go`). `devc box data-worker` reads one JSON `DataRequest` on stdin and prints one `DataResult`; operations `setup`, `seal`, `unseal`, `rm`, `trash-restore`, `trash-empty`, `ls`, `reflink-save`, `savepoint-drop`, `restore`. **Deviations and choices.**

1. **Work zones are `2000:1000 0775`, not `1000:1000 0755`.** A box-owned directory inside the sticky, vault-owned data root can still be renamed or removed by its owner, which contradicts "zone directories cannot be renamed or removed by the box" (section 1) and test item 1. Vault-owned with group write keeps the directory itself immovable while everything inside stays ordinary for the box and the host user. Intermediate directories of zone paths (`a` in `a/b`) are `2000:1000 1770` like the data root, so a zone cannot be moved by moving its parent.
2. **restic sees the whole project directory read-only at `/project`, not just the data root.** Podman resolves bind sources on the host and follows symlinks; the project directory's path is host-made, so nothing a box planted can change what is mounted (`.devc` is 0700 vault and unreadable to restic's user). Before every restic save the setup worker re-checks the layout and lists the excludes.
3. **Every mutating data command runs the setup worker's layout step first** (inside the same worker), so seal, rm, save and restore also work on a project whose box has not been started since C06, and always on a checked layout. A `.devc` that the box created (owner 1000) is refused; one left by a crashed worker (owner 0) is adopted.
4. **rw-mounted data projects.** A box that mounts another data project read-write (`[[mounts]] mode = "rw"`) gets that project's input zones as read-only nested mounts too, and its `up` runs that project's setup. This closes the C02 note: no running box can then write another project's inputs or swap its zone directories while that project's box starts.
5. **Seal records** go to `.devc/seals.jsonl` with `op` = `seal` or `unseal` (unseal records are an addition); `data ls` takes sealed entries from the tree (vault-owned children of sealed zones) and time/size/commit from the last seal record. Sealing an entry that is sealed already re-walks it (completing an interrupted seal) but writes no record and reports "sealed already". A regular file directly in a sealed zone can be sealed too.
6. **Restore granularity** is per entry (see above), with identical entries left in place; the work order's "anything in the way" is everything that differs.
7. **Savepoint paths** are recorded as `paths: ["."]` plus `exclude` (input zones and the sealed entries at save time); a restore of an excluded path is refused with that reason.
8. **The realm directory is made `0700` for every project**, data or not (it is shared by the realm's projects).
9. **Before-session savepoints fail the session** when they cannot be taken (README rule 6); turn `before_session` off to start anyway.
10. **In-box command names.** Plan 3.3 lists `box seal-worker` and `box copy-worker`; there is one `devc box data-worker` taking a JSON request with an operation, plus `devc box data-links` (run in the box itself).

**Deviations and choices.**

1. **Restart without recreation.** `podman init` works on a stopped (exited) container and creates a fresh network namespace, so a stopped box of level internet is started with init → rules → start; it is not removed and recreated (the container layer, including `devc root` changes, survives). A failed restart stops the box again instead of removing it (rollback semantics of C03r).
2. **Host addresses in the rules.** Besides the nine ranges, the rules reject the host's own IPv4 addresses outside them (a server's public address would otherwise reach host services through the engine's NAT). The canary tries every host address (private or not) plus the host alias, not only private ones.
3. **Canary from both sides.** The host counts connections its listener accepts as well as reading the box's report, so a box cannot pass the check by lying.
4. **Resolvers.** All IPv4 nameservers of the box's resolv.conf are allowed on port 53. On this host that is `10.0.2.3` (slirp4netns) and `192.168.122.1`, the LAN router (see LEFTOVER).
5. **`up --all` starts existing boxes only** (running or stopped) and creates none; `down --all` stops every running box of the configuration. Both continue after a failure and exit 1 if any box failed.
6. **Forward details.** Box gone = not running or a different PID (a restart ends a forward). A detached forward is devc itself (`forward serve`), started directly with the listener as file descriptor 3 in its own session, logging to `<runtime>/forwards/<id>.log`; the parent opens the listener so the port and errors are reported synchronously. Forward IDs are `f` plus six hex digits. `forward` starts the box like `sh` does.
7. **Box init removes a stale readiness marker** (not in the work order): a plain `podman start` that fails left the marker of the previous run behind.
8. **Self-test item `nftables`** (not in the work order) gives the escape suite its "rules cannot be listed or changed" proof without `nft` in the image.
9. **Escape suite reuse.** The data layout and sealed-entry attempts of `TestData` moved into `layoutEscapes`/`sealedEscapes` (extended by overwrite, rename inside, replacing with a decoy and a symlink) and are called from both tests; the git host-side traps reuse `hostileRepository` from `TestGit`. A box of another realm runs during the suite; the second box of the same realm serves on all its addresses.
10. **Doctor statx probe** uses `create`/`start`/`inspect`/`rm` instead of `run --rm`, because a hung worker cannot be killed while its fuse request is pending; devc ends the container's own fuse-overlayfs process (it is the user's process; nothing else is touched).
11. **`init <url>`** validates the URL like a project upstream (no `ext::` or other transport helpers) and clones with `-c protocol.ext.allow=never`, the user's own git configuration and credentials, attached to the terminal.
12. **Example dotfiles** are now copied into every test box (they are part of `examples/config`); nothing in the suite depends on them.

**How to exercise.** `./dev build`; with a configuration whose realm uses the default level: `bin/devc up <ref>` (look for the rules with `podman unshare nsenter --net=$(podman inspect -f '{{.NetworkSettings.SandboxKey}}' <box>) nft list table inet devc`), `bin/devc run <ref> -- bash -c 'exec 3<>/dev/tcp/192.0.2.1/9'` (refused), `podman stop <box>; podman start <box>` (the box stops again; see `podman logs`), `bin/devc forward 8888 <ref> [--detach]`, `bin/devc forward ls|stop`, `bin/devc doctor [--fix]`, `bin/devc init --example --config-dir /tmp/x`. Tests: `./dev test ./internal/netpolicy/ ./internal/box/ ./internal/boxside/ ./internal/doctor/`; `./dev itest -run 'TestNetwork|TestForward|TestInitExample|TestDoctorStatx|TestEscape|TestRecreateKeepsState' -v`.
