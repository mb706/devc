# Response to review C, part 1

Chunk C12r1. One paragraph per finding of `C1-review.md`, resolved as the decisions table of `docs/dev/chunks/C12r1-review-fixes-daemon.md` directs. Code references are to the working tree after C12r1; tests are unit tests unless marked as integration tests.

**C1-01: fixed as decided.** `session.Store.Claim` (`internal/session/owner.go`) records the owner of every session ID in `durable/session-owners/<id>`, created exclusively when ingestion (or a host event) first touches the ID. Journals from before this record exist are resolved once: the project whose journal began first owns the ID. Ingestion refuses a spool file whose session belongs to another project. Nothing of it reaches any journal. The refusal is kept in the offending project's own bookkeeping (`refused` in its `spool-offsets.json`, so it is reported once) and reported as a warning (daemon log, `devc ps`). The daemon's hub indexes sessions by `(project, ID)`. Commands are bound to the project when they are accepted (`Command.Ref`, new `Receipt.Ref`), and a restart takes the stored pair, never the ID alone; a receipt stored without a project is refused. Every method that names a session takes an optional `ref`. Without it, the ID must be unique: an ambiguous ID gets an error or a refused receipt that names the projects. Cursors and subscription filters take `<realm>/<project>/<id>` keys. Bare IDs from older clients still work and stand for every session with that ID. The CLI accepts `<realm>/<project>/<id>` and passes the project whenever it resolved one. Tests: `TestSessionOwnership`; `TestCommandsSurviveRestart` (a planted older journal in `demo/analysis` does not rebind a stored command, and the bare ID becomes ambiguous); `TestSubscribeKeys`.

**C1-02: fixed as decided.** At the end of every successful start (`afterStart`), `box.Manager` writes `local/boxes/<realm>/<project>/capabilities.json` (`internal/box/capabilities.go`). It holds the container ID, the granted secrets including harness tokens, `grants.ssh` and `grants.ssh_allow`. The record is removed before every start and at `down`, `rm` and rollbacks. `host.secret`, `host.gate` and `devc gate-exec` allow only what both the record and the current configuration grant. For SSH, a host is read-only when either says so, and the allow list is the intersection. A missing record, or one for another container, refuses with "restart the box". Tests: `TestCapabilities`, `TestUpCreatesAndIsIdempotent` (written at up, gone after down), `TestSecrets`, `TestGateStreams` and `TestExecStartedWith`; each covers a grant added after the start, a grant removed, a missing record and a foreign record.

**C1-03 and C1-04: fixed as decided.** `muxGuard` (`internal/daemon/muxguard.go`) sits between the box socket and yamux on the daemon side. It parses frame headers in both directions and skips payloads without counting them. It counts the box's new streams (256) and its ping/go-away frames (32) per 10 s window. It tracks every stream until both sides have closed it or one has reset it (at most 128 open or half-closed). When a budget is exceeded, it closes the connection. The channel then reports `refused` ("the box exceeded the channel's limits: …") and reconnects with growing backoff, because a channel closed this way does not count as a normal end. The budgets are constants at the top of the file. Data is never counted. Tests: `TestMuxGuard` (64 MiB on one stream in odd pieces, open/close churn beyond the window, half-closed streams, a stream flood, a ping flood, garbage); `TestHostileTransport` (a real yamux peer flooding pings or holding streams; the daemon keeps answering).

**C1-05: fixed as decided.** The relay hooks are now `pre-receive`, `update` and `post-receive`. `pre-receive` refuses the whole push above `gitx.MaxPushRefs` (1000 refs) and records the box's branches for the box-tip rule. `update` checks the policy and then writes the bank ref, box tip or tag record in one `update-ref` transaction (`gitx.RecordUpdate`, with `core.fsync=reference`). The objects are out of quarantine at that point. If the transaction fails, the update is refused. `post-receive` only forwards and reports (`gitx.ReportPush`). Test: `TestRelayHooksRecordFirst` (CLI) runs real `git receive-pack` with the test binary as hooks. An accepted push has its bank ref and report. A protected branch, an update whose bank ref cannot be written (a ref in the way), a push of 1001 refs and a push over the relay budget all leave no bank ref and no branch.

**C1-06: fixed as decided.** `save` returns its error. `setDelivering` puts the in-memory outcome back to `accepted` when storing fails. Delivering is now stored inside `target.begin`, after the input gate and immediately before the first key, for every kind (send, answer, interrupt, keys, stop, and start's first step). On failure nothing is typed: the command stays accepted and is tried again after `persistRetry` (10 s). Test: `TestDeliveryChecks` (a full disk at the delivering transition: no paste, the receipt stays accepted, delivered once there is room).

**C1-07: fixed as decided.** `receive.maxInputSize` is set on every receive-pack (`git.max_push_size`, default `2g`). The daemon also stops feeding the stream to git after that limit plus 64 MiB for commands. `pre-receive` refuses a push when the relay, which includes the incoming quarantine at that point, exceeds `git.relay_quota` (default `20g`), with a message naming the setting. Both settings are validated and parsed by `config.ParseSize`. Git's CPU and memory are not limited further (see LEFTOVER). Tests: `TestServeCall`, `TestRelayHooksRecordFirst` (quota), config validation.

**C1-08: fixed as decided.** Every queued batch counts its bytes, per subscriber (32 MiB) and for the whole daemon (256 MiB). A subscriber that would exceed either is disconnected and resumes from its cursor. Its queue is released when it goes. Test: `TestSubscriberByteBudget` (one slow subscriber; ten slow subscribers hitting the daemon-wide budget first; nothing left counted afterwards).

**C1-09: fixed as decided.** Git and sshd streams are wrapped in `rawStream`. Every write gets a deadline (`streamStall`, 2 minutes). When the operation ends, or the worker's context does, both deadlines move to the past and the stream closes. This unblocks the stdin feeder and the output copy before the box lock is released. Test: `TestRelayStreams` asks receive-pack for the advertisement of 20,000 refs (about 1.8 MB) and never reads it; the box lock is free again after the (shortened) stall limit. With the limit at 10 minutes the same test fails.

**C1-10: fixed as decided.** `requests.Store.Put` compacts a log that passes 4 MiB. It keeps the latest state of every pending or approved request and the 200 most recently changed closed ones, and replaces the file by rename. New requests are refused while a log stays above 16 MiB; changes to existing requests are still stored. `Find` and `requests.list` skip an unreadable log and still serve the other projects; when a request is found nowhere, the error names the unreadable logs. Tests: `TestStoreCompaction` and `TestRequestLogs` (decisions and lists beside a log that is a directory).

**C1-11: fixed as decided.** Approved requests run on one executor: 2 workers and 32 queued places for the whole daemon. An approval takes a place first. When none is free, a local or hub approval is refused as busy and the request stays pending, and an automatically approved kind is refused at creation. Pending and approved-but-unfinished requests together count against the per-project limit of 100. Test: `TestRequestExecutor` (one worker, two places: a busy automatic request, a busy approval that stays pending, approved requests counted, one run at a time).

**C1-12: fixed as decided.** `gate.Keys.NewBoxKey` checks with `secrets.CheckMemoryFS` that the runtime directory is memory-backed before `ssh-keygen` runs, unless `DEVC_ALLOW_PERSISTENT_SECRETS=1` (`Keys.AllowPersistent`, set by the CLI from the same variable as secret delivery). Test: `TestServerPrepare` (on a disk-backed directory the key is refused and ssh-keygen does not run).

**C1-13: fixed as decided.** `session.answer` binds the accepted answer to the question pending at acceptance (`Command.Question`). The question is checked again immediately before delivery: before handing the answer to a hook, and in `begin` before typing on screen. A different pending question, no question, or a hook waiting for another question refuses the answer as stale. It never falls through to the screen. Test: `TestDeliveryChecks` (q1 replaced by q2 while the answer waits in the gate; a hook waiting for q3).

**C1-14: fixed as decided.** `begin` also checks, after the gate and immediately before the first key, that a queued send still finds the session at rest. If not, the command goes back to waiting (`outcomeRequeue`) without being typed. Test: `TestDeliveryChecks` (a person submits a turn while the queued send waits in the gate; it is typed only after the turn ends).

**C1-15: fixed.** Polling one project, which happens after every ingestion and host event, now also tails the journals of ended sessions. The periodic poll does so every tenth pass. Appended events, such as `seen` after the end, are published; the lifecycle stays ended (`SessionView.Apply`). Test: `TestSubscribeEndedAndCold`.

**C1-16: fixed.** A subscription whose window reaches a cold session (one that ended before the default window) loads that session and replays it; nothing depends on earlier calls. Test: `TestSubscribeEndedAndCold` (a session ended 60 days ago, with a 90-day window).

**C1-17: fixed.** A journal read error during a replay sends `missed` for that session, with the last seq sent, instead of a silent catch-up. Test: `TestReplayFailure` (the second read fails after one event was sent).

**C1-18: fixed.** A status poll that finds an expired request reads the log again under the request lock, and only a request still pending expires. The outcome of an executed request replaces the stored state only while that is still `approved` (`transitionLocked`). Test: `TestRequestLogs` (an approval lands between the poll's read and its lock; the request stays done).

**C1-19: fixed.** `submit` copies the acceptance receipt before it dispatches the record, and returns that copy; every other receipt an API caller sees is read from its file. No dedicated test: the race needs the race detector, which `./dev` cannot run (CGO is off). The fix holds by construction.
