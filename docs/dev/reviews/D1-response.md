# Response to the final review, part 1

All twenty findings of `D1-review.md` and the unconfirmed D1-21 are resolved in chunk C19r1 as the work order's decisions table directs. Tests named below are unit tests unless marked integration.

**D1-01 — fixed.** The router refuses (403) a WebSocket upgrade or a request with a method other than GET and HEAD whose `Origin` is not exactly `http://<requested host>`, a request with several or opaque origins, and any request whose `Sec-Fetch-Site` is not `same-origin`, `same-site` or `none`, except a top-level navigation by GET (`Sec-Fetch-Mode: navigate`, `Sec-Fetch-Dest: document`). Programs that send neither header pass. `daemon.TestRouterRefusals` covers seventeen browser cases (another realm's box, another port of the same box, `null`, form posts, cross-site images, fetches and frames, navigation by POST, links, typed URLs); integration `TestLocalURLs` opens a WebSocket from another origin and gets 403. A frontend on one port calling an API on another port of the same box is now refused too; the guide says so.

**D1-02 — fixed.** The upstream reader of a plain HTTP request sits behind a limit of 64 KiB per response head (reset for each interim answer) and a fixed deadline for the whole head (`ResponseTimeout`, default 5 minutes from the end of the request); exceeding either closes the upstream and answers 502. `netpolicy.TestProxyResponseHead`: an endless header line, endless header fields and a trickling head are cut off and the upstream's writes fail; a 60 KiB head with an interim answer still works.

**D1-03 — fixed.** Every archive endpoint takes a place in a global and a per-machine admission (`max_downloads`/`machine_downloads` for reads, `max_uploads`/`machine_uploads` for uploads) before it reads a body or walks a tree. The summary comes from the per-machine usage the hub keeps (counted once, then kept current), and indexes come in pages of at most 2000 entries (`?after=`, walk order; subtrees before the cursor are skipped); walks stop when the request is cancelled, and so does a prefix hash. `hub.TestArchiveAdmission` fills each machine's and the global places for the summary, index, download, hash, secrets read, upload and secrets push; `TestArchiveIndexPages` pages 2,500 nested entries once each; the client (`fleet.Client.Index`) reads pages that must advance, at most a million entries.

**D1-04 — fixed.** A secrets push takes an upload place before its body is read; the stored bundle counts against the machine's and the realm's quota and the file limit, and removed versions are taken off again. A machine may hold at most `max_realms` (default 100) realms, archive and secrets together. `hub.TestSecretsQuota` exceeds the machine quota, the file limit and the realm limit (through secrets and through the archive).

**D1-05 — fixed.** Relays keep incoming objects packed: `transfer.unpackLimit`, `receive.unpackLimit` and `fetch.unpackLimit` are 1 in the relay configuration, on every receive-pack and on every fetch from a box. Measured with git 2.43 before choosing thresholds: a 300 MB push grew the quarantine by 304 MB (its pack); twenty one-byte variants of a 50 MB incompressible object grew a default relay by 1,000 MB and a relay with these settings by 50 MB (the thin pack's base, added once). Before receive-pack the daemon requires 1 GiB free on the state file system and a relay within its budget; while it runs, a watchdog measures the quarantine every 200 ms and ends the push when the relay would exceed `git.relay_quota` or less than 512 MiB would stay free, then removes what the push left. `pre-receive` still checks. `daemon.TestPushWatchdog` (growth beyond the budget, a filling disk, nothing within the budget) and `TestRelayStreams` (refused without the reserve, and when it cannot be measured); integration `TestRelayService` pushes 300 MB of random data successfully and has a 60 MB push into a relay with an 8 MiB budget ended by the watchdog, leaving no quarantine.

**D1-06 — fixed.** Every CONNECT tunnel and every upstream connection serving a plain request is watched: its destination is checked against the policy at once, every 5 seconds, when an exception in force ends (`ProxyPolicy.Ends`), and when the daemon asks (`Tunnels.Recheck`, run by `net.sync`, which `devc net allow`/`revoke` now also call for name exceptions at level allowlist, and by the 5-second network loop). A destination no longer allowed, or a policy that cannot be read, closes the connection and is logged. `netpolicy.TestProxyTunnelsEnd` (expiry without any trigger, revocation, an allowlist change, an unreadable policy, a plain download); `daemon.TestNetProxy` revokes an exception and sees the tunnel closed within two seconds of `net.sync`.

**D1-07 — fixed.** The archive carries and restores only devc's ref namespaces (`refs/heads/`, `refs/tags/`, `refs/remotes/github/`, `refs/devc/bank|snap|tags|boxtip/`); anything else, `refs/replace/` and `refs/notes/` included, is reported as a conflict and not created. Every host git command runs with `--no-replace-objects` and `GIT_NO_REPLACE_OBJECTS=1`, and so does the context worker's git. `fleet.TestRestoreRefusesReplaceRefs` restores a crafted archive into a relay with a banked commit; a replacement ref planted in the relay afterwards is neither interpreted nor archived. `gitx.TestHostCmd` checks every mode.

**D1-08 — fixed.** Downloads hold a place in the global and the calling machine's read admission, and every write has a deadline of 30 seconds (`archiveStall`); a download whose deadline cannot be set is refused. `hub.TestArchiveDownloadStall`: a client that stops reading a 64 MiB file loses it and the only place is free again within seconds.

**D1-09 — fixed.** A folded run holds at most 200 tool calls (a longer run continues in a new one), each call carries its seq, and trimming the window also drops the calls of the first run that lie before it. Expanded rows are bounded by the run size. `web/check.sh` checks 3,000 tool events in the page's own module and a dev session with 210-call turns on screen.

**D1-10 — fixed.** A successful answer whose body cannot be read, and a command answer that is not a receipt (no outcome, another command ID), raise an error marked uncertain; commands retry it with the same ID and then keep it pending with its ID and parameters. `web/check.sh` serves broken bodies to `api.get` and to a command, and checks that the command stays pending under its own ID after attempts that all used it.

**D1-11 — fixed.** The receipt directory is synced after the link of a new record and after the rename of a replaced one; a failed sync fails the step (a new record is taken back so a retry starts afresh), so `delivering` counts only once it is durable. `daemon.TestReceiptStore` observes the sync after each step and makes it fail; `TestDeliveryChecks` makes the sync fail for `delivering` only: nothing is typed until it works.

**D1-12 — fixed.** Session summaries carry the stream position they are current at: a stream change its event ID, a detail read the position the hub took before reading, a snapshot its position. A summary older than the one held is not applied. `web/check.sh` applies a stream summary with question q2 and then a detail answer from an earlier position with q1: q2 stays.

**D1-13 — fixed.** **Load earlier** is always offered while older events exist. A page that would make the window exceed 1,000 events moves it back, dropping the newest events, and marks it not live; live events then only settle the outbox, and **Back to the latest** reads the newest events again. `web/check.sh` pages a dev session of about 2,600 events back to its start (holding at most 1,000), and returns to the latest.

**D1-14 — fixed.** The class of a shared-state file comes from the harness manifest on the machine (`Harness.TranscriptStatePatterns`, with `**` support, `archive.ClassOf`) and is recorded with each generation on the hub; host-written logs are append-only. Append-only: when the inode or modification time changed, the whole uploaded prefix is hashed again and a mismatch starts a new generation (at most one per hour); every generation is kept. Mutable: any change of inode, time, size or mode starts a new generation, at most once per `[sync] mutable_interval` (default 6h), uploaded from a snapshot copied when it began; the hub keeps the newest three complete generations of a mutable file and drops older ones itself, never one recorded as append-only. Generation numbers only grow (the hub refuses an older one; lost bookkeeping starts after the newest the index shows). `fleet.TestFileClasses` (an interior change with the same size, head and tail; the interval; three kept; a transcript rewritten five times keeps all six generations), `TestSnapshotConsistency`, `hub.TestArchiveGenerations` (append-only generations survive later mutable ones of the same file).

**D1-15 — fixed.** A generation is marked complete with its length (`PUT …&final=1` on a file; the hub records it beside the file and the index reports `committed`). The machine marks it when an upload caught up with a file that did not change meanwhile. Restore uses the newest complete generation at that length and reports newer incomplete ones; without any complete generation it restores an append-only file's newest prefix and skips a mutable one, reporting both; archives from before completion marks restore as before. `fleet.TestCompleteGenerations` cuts a rewritten journal's new generation after one chunk and restores the complete one.

**D1-16 — fixed.** The listing has one limit end to end: the worker stops listing before its report would exceed 64 MiB (reporting the rest as skipped), the host captures exactly that much (`RunOptions.MaxOutput`) and treats a cut capture as an error, and the decoder accepts that much. A pass whose harness listing failed ends in state `incomplete` with the reason per realm (`devc sync status`, `devc hub status`). `boxside.TestArchiveWorker` (a lowered limit), `fleet.TestContainerWorkers` (a cut capture), `fleet.TestIncompletePass`.

**D1-17 — fixed.** Ref log lines go through the same bounded, rate-limited chunks as files, with 413 halving and resumption after a lost answer inside the line. A line cut off by an interruption is ended with a newline at the next resync (an invalid line readers skip), and readers ignore a last line without its newline. `fleet.TestRefLogChunks`: a 147 KB line in 64 KiB chunks, interrupted after its first chunk, then lost bookkeeping; the log replays and the relay restores.

**D1-18 — fixed.** The permission bits travel: the machine records them with each generation (`mode=`), exports carry them in the tar headers (also the archive worker's), and restores apply `mode & 0777 | 0600`; set-ID and sticky bits never travel. Import keeps the extractor's executable bit. `fleet.TestCompleteGenerations` (a 4755 hook arrives as 0755 through the hub and through an export), `boxside.TestArchiveWorker`.

**D1-19 — fixed.** A restore refuses a source of another realm (`Source.SourceRealm`), and `devc state import --realm` with another name than the export's is refused with the reason (the journals, request logs and ownership records name the realm). `state pull` restores only under the realm it reads. `fleet.TestCompleteGenerations` tries both.

**D1-20 — fixed.** An empty PUT with `final=1` creates an existing empty file (a generation of length zero) and marks it complete; without `final` it still only reports the length. A file truncated to empty becomes a new generation of length zero. `fleet.TestCompleteGenerations` (an empty marker file and a truncated log, archived and restored), `hub.TestArchiveGenerations`.

**D1-21 — fixed (treated as real).** The host's aliases from the backend facts — the hosts file's `host.containers.internal`, slirp4netns's gateway (the host's loopback with `allow_host_loopback`), pasta's mapped host address and named networks' gateways (`netpolicy.BackendHostAddrs`) — are rejected with the host's own addresses before the LAN exception set, and the start's canary tries them too. `netpolicy.TestGather`, `TestInstall`, `box.TestInternetLevel`; integration `TestNetworkExceptions` reaches a listener through `host.containers.internal` with a `lan` exception in force (refused) and checks that the alias and slirp4netns's gateway are in the rejected set before the LAN set. On this host the alias is the host's LAN address; a backend whose alias reaches the host's loopback could not be set up here.
