# Response to the final review, part 2 (D2)

Chunk C19r2. Every finding of `D2-review.md` (against `3cc8005`) and the unconfirmed D2-16 is resolved as the work order's decisions table directs. Tests named below are new unless marked as extended.

**D2-01 (desktop resources) — fixed.** New global `[gui]` with `memory = "2g"`, `pids = 512`, `cpus = 2` (`config.GlobalGUI`, validated; shown in `devc config show` and the example configuration). `gui.LimitArgs` turns them into `--memory`, `--pids-limit` and `--cpus` for the sidecar; a limit whose cgroup controller is not delegated fails `devc gui up` before anything is created or removed, and `memory = "none"`, `pids = -1`, `cpus = -1` switch a limit off explicitly, as for boxes. The image bounds the per-connection helpers: socat serves at most 64 X connections (`max-children`), and websockify runs under a small launcher that lets at most 16 handler processes exist at a time (further connections wait in the listen queue). Tests: `gui.TestLimitArgs`, `TestSidecarArgs` and `TestUpDownStatus` (extended: exact limit arguments, recorded limits), `TestUpFailures/limits cannot be applied` (no container, no forward; then switched off explicitly); `config` broken cases for `gui.*`; integration `TestGUI` (extended) reads `memory.max`, `pids.max` and `cpu.max` inside the sidecar (2147483648, 512, `200000 100000`) and holds 24 viewer and 66 X connections open from the box: exactly 16 websockify handlers and 64 socat children run, and the counts fall back once the connections close. While testing, TigerVNC's own blacklisting was seen to refuse a sixth unauthenticated VNC connection from 127.0.0.1 (see LEFTOVER).

**D2-02 (App token and drift) — fixed.** The start record now holds `github_upstream` (token modes) and `github_app_id`, `github_installation` (mode `app`). `Capabilities.GitHubToken(r, web)` delivers only when the mode, the repository (both upstreams parsed with the daemon's web base and compared as GitHub does) and the App identity are what the box started with; a record without the repository (an older start) gets nothing. The daemon mints for the repository of the grant. Tests: `box.TestGitHubCapabilities` (rewritten: changed upstream, owner, removed upstream, upstream no longer on GitHub, changed App, installation, removed App, old record; the same repository written another way passes), `daemon.TestGitHubToken` (extended: upstream changed while the box runs is refused, App changed is refused, restoring the configuration delivers the cached token again).

**D2-03 (installation and owner) — fixed.** `Minter.verify` looks up the installation for the repository with the JWT (`GET /repos/{owner}/{repo}/installation`) even when `installation_id` is configured: its account must be the repository's owner and, if configured, its ID the configured one. A metadata-only probe token for the repository's name then reads `GET /installation/repositories`, which must list exactly that repository; its ID is kept, the probe is revoked (`DELETE /installation/token`). Real tokens are minted with `repository_ids: [<id>]`; an answer that lists other repositories is revoked and refused. A failed mint forgets the verification; it is trusted for at most 24 hours otherwise. Tests: `github.TestMinter` (rewritten against a fake with installations per account: configured installation of another account, no installation, an installation whose account is not the owner, a probe that sees another repository, an answer with an extra repository; controls that mint) and the daemon and integration fakes, which now check the ID restriction (`TestGitHubTokens` expects `repository_ids: [4711]`).

**D2-04 (service streams) — fixed.** Once a request head is accepted, the stream gets a limit of `limits.timeout` plus a grace (5 s): `relayConn` clamps every deadline the HTTP server or the proxy sets (and the per-write stall deadline) to that limit, so a box that stops reading or never finishes its body releases the stream, its relay place and the handler; a timer closes the stream (only the stream) at the limit as a backstop instead of waiting on the worker's context. Test: `daemon.TestServiceStreamDeadlines` (a 16 MiB answer the box never reads, a body announced as 100,000 bytes that stops after seven; the relay place is held while the exchange runs and freed within about two seconds; the channel stays connected and serves the next request). Without the fix the test fails after 10 s with the place still taken (checked by reverting the change).

**D2-05 (browser probe) — fixed.** `browserAnswers` uses a client without a proxy that never follows redirects (`http.ErrUseLastResponse`); a 3xx is "no browser found". Test: `cli.TestBrowserProbeNoRedirect` (301, 302, 307, 308 to a recording server are not followed, with a default client following the same redirect as a positive control; a real `/json/version` answer is recognised).

**D2-06 (truncated preview) — fixed.** A dry run whose capture was cut (`Result.Truncated`) is refused (`ErrPreview`, "transfer fewer paths at a time"); `ParseItems` accepts only itemized lines (an 11-character change code, which may contain spaces, a size, a name) and rsync's two known stdout messages ("created directory", "skipping non-regular file"), anything else is `ErrPreview`; `Totals` refuses a sum beyond `int64`. Pull and push both use these. The execx fake now applies the capture cap like the real runner. Tests: `data.TestParseItems` (rewritten), `TestSyncPreviewAndLock` (cut, unparseable and overflowing previews refuse before any transfer and leave no staging directory; the same preview within the cap transfers).

**D2-07 (short credentials) — fixed.** `svclogin.MinCredential = 8`. `CheckCredential`/`HeaderCredential` refuse a header credential with any secret part shorter than that (the value; the token after a scheme; for `Basic` the decoded user:password and the password); the daemon answers 503 naming `devc secret set`, and `devc service status`/`ls` show `invalid-secret`. Cookie values under 8 characters are refused when a login stores a jar (and when a stored jar is read back). The scrubber now scrubs every value it is given, without a length threshold, and the proxy refuses (503, nothing sent) a credential with a part shorter than 8 characters as a last check. `ScrubValues` no longer treats the scheme word as secret and decodes Basic only after `Basic`. The example `login.sh` leaves short cookies out. Tests: `svclogin.TestScrubValues` (rewritten), `TestProxyShortCredential` (four short shapes refused with nothing reaching the upstream; a long key of the same shape sent), `TestParseLoginOutput` and `TestLogin` (short cookie values).

**D2-08 (login errors) — fixed.** `Login.Run` passes every error it returns through the same redaction as the standard error (all secret values, longest first, no length threshold), whether it came from the output, the engine or elsewhere. Output validation no longer repeats output: JSON errors are described by kind and byte offset (an unknown field's name is not shown), cookies are named by their position only, domains are not echoed; `ParseJar` does the same. Tests: `TestParseLoginOutput` (eight outputs carrying a marker in a field name, a value of the wrong type, a domain, a cookie name, a truncated string: no message contains it), `TestLogin` (password as a field name, as a domain, in an engine error and in stderr: never in the error).

**D2-09 (token cache) — fixed.** `Minter.Token` takes the project scope (`<realm>/<project>`), parses the key before any cache lookup, and keys both the token cache and the verification cache by API, scope, App ID, the SHA-256 fingerprint of the key's public half, the configured installation and the repository (tokens also by permissions). Tests in `github.TestMinter`: another project gets its own token; an invalid key fails although a token is cached for that project; another valid key is refused by the fake (JWT) instead of receiving the cached token; the right key still gets it.

**D2-10 (push backups) — fixed.** Backup directories are `.devc-backup/<stamp>-<12 hex>` with a random ID per push (`Service.Rand` for tests); `RsyncArgs` accepts only that form. Test: `data.TestServicePush` (extended: a second push in the same second gets another directory), `TestRsyncArgs` (a backup directory without ID is refused).

**D2-11 (concurrent pulls) — fixed.** Pull and push take `local/locks/sync-<realm>-<project>-<remote>.lock` (flock) for their whole run, before the staging directory is chosen; another operation with the same remote is refused after 3 s with a clear message, another remote is not affected. With the lock held, a staging directory found by `pullStaging` belongs to an interrupted, inactive pull. Test: `TestSyncPreviewAndLock` (pull and push refused while the lock is held, no rsync run; another remote works; after release it works).

**D2-12 (manifest truth) — fixed.** The pull-in worker also reports `remote_digests`: the digests of the same entries in the staged tree, which is what the remote had. Pull records keep `digest` (this machine's copy after the merge) and add `remote_digest`; `data status` compares a remote's last pull by `remote_digest`, never by the local digest, so a pull that skipped a sealed entry or kept local-only files never shows the remote as matching. Push records carry no remote observation; status marks a remote whose last record is a push of the entry as it is now with `>` (sent; the remote may keep other files). Test: `data.TestPullRemoteObservation` (a sealed entry that differs, an identical entry, an entry with local-only files: only the identical one matches the remote; this machine's copy matches in all three); `TestStatusAndVerify` (extended).

**D2-13 (source checksums) — fixed.** A candidate without a checksum is downloaded only when it says the registry publishes none (`unchecked`: CRAN's archived versions, GitHub tarballs); otherwise a missing, malformed or unknown checksum refuses the download. PyPI must give a 64-hex sha256; npm's integrity string is parsed as Subresource Integrity (sha512, sha384, sha256, sha1, several tokens, options), the strongest valid one is used, digest lengths are checked, and integrity that is present but unusable is an error even when a shasum exists; without integrity a 40-hex shasum is required; CRAN's current release must have a 32-hex MD5 in `PACKAGES`, which is now read for every CRAN download. Test: `depsrc.TestFetchChecksums` (eleven npm dist shapes, four PyPI digest shapes, CRAN without MD5, archived CRAN version and controls).

**D2-14 (cached sources) — fixed.** A concrete version (any registry version, or a 40-hex commit for GitHub) found in the cache is returned before any network access; when a registry normalised the version asked for, an alias file (`.alias-<asked>`) beside the version directories maps it to the canonical one. Test: `depsrc.TestFetchCachedOffline` (no requests while the registry is up, the same answers after it is closed, the alias answers offline; a branch, the latest release and an uncached version fail without the registry).

**D2-15 (credential searches) — fixed.** The service tests use `credentialSearch`: the search first finds a planted control in a file and in a running process's environment, every run must exit 0 and end with a marker, and only then are the credentials searched. The GitHub tests' `boxSearch` also requires its end marker now.

**D2-16 (encoded separators, unconfirmed) — treated as real and fixed.** `NormalizeTarget` refuses a percent-encoded reserved character (`: / ? # [ ] @ ! $ & ' ( ) * + , ; =`) in the path, besides the encoded slash, backslash, percent and control characters it refused already; other encodings (space, `"`, non-ASCII bytes and the like) are kept. `config.CheckRulePath` refuses the same in rules. Tests: `TestNormalizeTarget` (extended with `/api/..%3Bx/admin` and every reserved character), `TestCheckRulePath` (extended).
