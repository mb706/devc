# Response to the accuracy review G1 (foundations, configuration, toolbox, harnesses, boxes, the box side)

Chunk X15a. Every finding was checked in the code; all 20 are right and were fixed where they stand, together with the same belief elsewhere in the model. Code comments changed, code did not (`./dev explore comments-only`). Gaps in the code are listed in `docs/dev/LEFTOVER.md` part 7, "Found by the accuracy review"; Part B's verdicts are recorded in part 7 under X4 and X5.

**G1-01 (the capability record is rewritten without a restart) — fixed, and a gap in the code.** `box.Manager.up` finishes the start of a running box without its readiness marker by calling `afterStart`, whose `recordCapabilities` writes the record from the configuration of that moment; the marker is box-writable, and every `sh`, `run`, `root`, session start, `worktree`, `forward`, `editor` and `gui up` goes through `ensureRunning` to that path. `box-lifecycle.md`: the invariant now says what holds (never more than today's grants and the record devc wrote when it finished a start of that container; nothing without a record for its container ID); the capability-record paragraph, the `up` list and a new "What can go wrong" item say when the record is written again. The same belief ("adding a grant needs the box brought up again", "granted when the container started") was corrected in `secrets.md`, `allowlist-proxy.md`, `ssh-gate.md` and `github.md` invariants (now "in the start record"), `flows/secret-request.toml`, `flows/box-up.toml`, the glossary's capability record and allowlist, `layout.toml`, and the file comment of `internal/box/capabilities.go`. LEFTOVER part 7, item 1.

**G1-02 (credentials only in the memory-backed secrets directory) — fixed.** The invariant in `toolbox-and-harnesses.md` now covers token and key credentials only, names `DEVC_ALLOW_PERSISTENT_SECRETS` and the daemon path; the "Credentials leak" item says that a `shared-home` credential is the vendor's file in durable realm state that the realm's boxes can write (`harness.BoxHooks.Contribute` mounts `harness/<id>/home` read-write; `config.validateHarness` requires strategy `shared` for `shared-home`). The override was added where "memory-backed" stood alone: `flows/harness-login.toml`, `secrets.md`, the glossary's runtime directory and secret delivery.

**G1-03 (the readiness marker is not authenticated) — fixed.** `isReady` and `afterStart` only `Lstat` the file. The `box-init-and-agent.md` invariant now says what `clearReady` guarantees (a marker of an earlier start never counts), with `TestUpRollsBack` ("restart of a stopped box fails" shows a stale marker is not counted) instead of `TestInitWritesReadyAndWaits`; its "Ready only after the network check" decision says the host does not take the marker as proof and checks from outside. Corrected also in `box-lifecycle.md`, `network-levels.md`, the glossary, `layout.toml`, the channel `podman-box` in `system.toml`, and the comments of `clearReady`, `isReady` and `State` in `internal/box/lifecycle.go`.

**G1-04 (a plain `podman start` and a record left behind) — fixed.** `RemoveCapabilities` runs only in `publish` and `cleanup`; the daemon's identity check is the container ID (`daemon.Daemon.startedWith`), which a restart keeps. The bullet in `box-lifecycle.md`, the capability-record paragraph, the glossary and `layout.toml` now say that a box stopped outside devc keeps its record.

**G1-05 (`down` and `rm` stop unbanked on configuration problems) — fixed.** `cli.bankHook.BeforeStop` returns nil with a warning when the configuration has problems (finding B2). The invariant names the exception (a recreation cannot meet it: `Up` refuses problems first), and the "down and rm" paragraph says so. `flows/box-down.toml` already did.

**G1-06 (no symlink at a mount source) — fixed.** `EnsureBeneath` resolves the trusted root with `EvalSymlinks`; sources outside devc's directories get only `checkRealDir` of the last component; `prepareMountPoints` checks before Podman mounts by path. The `isolation.md` invariant now states exactly what is refused and where; the mounts paragraph says the roots may be symlinks; "Redirecting a mount" names the race with a realm-shared parent, an accepted limit (LEFTOVER part 5).

**G1-07 (no process holds a capability) — fixed.** `Manager.Root` sets `Privileged`, rendered as `--privileged`. The `isolation.md` invariant names `devc root` as the one exception, with `box.Manager.Root` among its references; the text already said so.

**G1-08 ("at the next devc up") — fixed.** Delivery happens only in `publish`, which the "running and ready" case of `up` never reaches. `flows/harness-login.toml`: the section is "At the box's next start", the step says which commands start the box and, in its detail, that `up` of a ready box delivers nothing and that daemon delivery reads the current value at every launch; the step that stores the secret notes that the CLI's message "'devc up' delivers it" is true only of an `up` that starts the box (a smaller item in LEFTOVER part 7). The logins paragraph of `toolbox-and-harnesses.md` had the same claim and was corrected.

**G1-09 (diagram `box-states`: `starting → absent`) — fixed.** The edge now reads "fails; created now: rm"; a new edge `starting → stopped` ("fails; existed: stopped", `startStopped`'s `rollbackStop`) and a loop on `starting` ("finishing fails: kept", the case in `up` that leaves a box it did not start running) were added. Checked at both widths.

**G1-10 (`Remove` on a container already gone) — fixed.** The `down and rm` paragraph says that `rm` then skips the after-stop hooks, so open sessions stay open, unlike `down`. This is X5 item 3 in LEFTOVER part 7 (confirmed, low).

**G1-11 (root log only with an env) — fixed.** `Root` appends to the root log only when `r.Env != ""`, and `config.validateProject` makes `env` and `image` exclusive. The paragraph says that a project with its own `image` logs nothing; the same was added to X5 item 5 in LEFTOVER part 7.
