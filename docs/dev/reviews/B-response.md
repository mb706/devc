# Response to review B

Chunk C07r. One paragraph per finding, in the review's order, resolved as the decisions table of `docs/dev/chunks/C07r-review-fixes.md` directs. Code references are to the working tree after C07r; tests are unit tests unless marked as integration tests.

**B1: fixed, with one addition to the decision.** Between rules and start, `startBox` (`internal/box/lifecycle.go`) asks `Installer.Bind` (`internal/netpolicy/binding.go`) for the namespace's inode, read through `podman unshare stat` on the same path the rules went into. Bind also checks that inode against the main process's own `/proc/<pid>/ns/net` when the host can see it. The result is written to `netns.json` in the box's read-only `/etc/devc`; every devc start removes the old file first. `devc box init` checks this record before the sentinel (`boxside.NetworkCheck`), and the canary still runs after the start. **Addition:** a test on this host showed the engine giving the restarted box's namespace the same inode four times in a row, so an inode-only record would pass a plain `podman stop; podman start`. The record therefore also holds the start time of the box's PID 1 (identical from host and box, and new with every start) and the boot ID. On a running box of level internet, `up`, and every command going through `EnsureRunning` (`sh`, `run`, `root`, sessions, forwards), now checks from the host that the record matches the engine's namespace and main process, and that `nft list table` succeeds through the same entry path. A box that fails is stopped and started properly. Tests: `TestBinding`, `TestBind`, `TestNetworkCheckSelection`, and the `TestInternetLevel` subtests "plain restart", "ready but unfiltered" and "namespace mismatch". Integration: `TestNetworkPlainStart` checks that the binding (not the sentinel) is what stops a plainly started box, and that a running box whose table was deleted from the host is restarted by `up` and by `run`.

**B2: fixed.** `withGit`, `push` and `wt new` refuse while `ProblemsFor` reports anything; this covers bank, pull and wt rm. `bank --all` (the timer) skips such a project, says why and exits 1. At `down`, `rm` and a recreation, the bank hook prints that nothing was banked and lets the box stop. Malformed patterns were already configuration problems at load time. Go's `path.Match` checks the whole pattern, so `protected = ["["]` is reported. As a backstop, `gitx.Protected` now fails closed: a malformed pattern protects every branch. Tests: `TestGitRefusesBrokenConfig` (CLI; nothing runs), `TestPlanBankBoxTips` (malformed pattern) and `TestCheckNameAndMatches`.

**B3: fixed.** New `devc ingest [ref] [--all] [--quiet]` (`internal/cli/sessioncmds.go`) ingests and reconciles. `devc bank` ingests its box first, relay or not. `bank --all` ingests every project before banking. The timer unit runs `ingest --all --quiet` as its own first step, so a failing or waiting bank does not hold ingestion back. Tests: `TestServiceText`. Integration: `TestBankAll` starts a session in a project without a relay, checks that it has no journal yet, runs `bank --all` and finds its events in the journal, with no `devc ps` in between; it also runs `ingest`.

**B4: fixed, with one addition.** `Bank` now returns a `*gitx.NotPreservedError` when work was not preserved: a failed snapshot command or fetch (all worktrees), a worktree's snapshot error, a snapshot commit that did not arrive, a snapshot ref or branch tip that could not be recorded. Policy skips and forward failures are not counted. `gitx.Preserved(err, worktree)` decides for one worktree. `wt rm` removes nothing unless the worktree's work was preserved, with or without `--force`; `--discard` skips banking and implies `--force`. A refusal from the bank hook wraps `box.ErrKeepRunning`, and then `down`, `rm`, `rebuild` and `up --recreate` leave the box running. `up --recreate` (and so `rebuild`) on a running box previously ran no stop hooks at all; it now banks and ends sessions like `rm`. **Addition:** `--no-bank` on `down`, `rm`, `rebuild` and `up`, so a box whose work cannot be banked can still be stopped deliberately. Tests: `TestBankNotPreserved` and `TestStopRefused`. Integration: `TestGit` makes `/tmp` unwritable in the box, then checks that `wt rm --force` and `down` are refused and the work is still there, and that `wt rm --discard` and `down --no-bank` succeed.

**B5: fixed.** `netpolicy.Pin` reads the engine's main PID and start time, notes the process's start time, opens `/proc/<pid>/ns/user` and `/ns/net`, and checks again: same process start time, and the engine still reports the same PID and start. The forwarder passes the two descriptors to every `nsenter` as `--user=/proc/self/fd/3 --net=/proc/self/fd/4` (`execx.Cmd.ExtraFiles` is new). The watcher ends the forward, and closes the listener, when the PID or the engine's start time changes. A connection accepted as the generation ends is dropped. Tests: `TestPin`; `TestForwarder` now checks the descriptors and that a restart with the same PID ends the forward. Integration: `TestForward` passes with the pinned namespaces.

**B6: fixed.** `appendJournal` makes the batch durable with fsync before the offsets file is written. On a failed write it truncates back. The next append starts on a new line, so a torn line that could not be removed stays isolated and is skipped. When the append fails, `ingestFile` returns the position from before the run. Journal events taken from a spool now carry a host-only `spool` offset (the end of their line; for a truncation note, where ingestion continues). The offsets file records the journal's sequence number. If a later journal event carries an offset, ingestion resumes there, so neither a partial append nor a lost offsets file causes a skip or a duplicate. Spool lines cannot set the field. Tests: `TestIngestAppendFailure` covers a write that fails outright, a write that stores one event plus half the next with a failing truncate, and a deleted offsets file.

**B7: fixed.** `Store.Refresh` takes an `Observe` function and reads the box's state under the ingestion lock, after ingesting. A session whose start is in the journal by then started before the observation, so a box seen stopped cannot be running it. A later start is still in the spool and is not touched. `RefreshStopped` is used only by down, rm and recreate, which hold the box lock. Test: `TestRefreshObservesUnderLock`.

**B8: fixed.** The relay records the box's tip per branch in `refs/devc/boxtip/<branch>`. A changed head and its box tip are written in one transaction. Tips that move no head are recorded in a batch, then one by one if the batch fails. `PlanBank` leaves a branch alone when the box's tip equals the recorded one. `InitBox` records the tip of the branch it checks out, so a pull before the first bank is kept too. Adopting a clone passes no box tips and behaves as before. Tests: `TestPlanBankBoxTips`, and `TestEndToEnd`, which banks after a pull, then a merge, then a new commit. Integration: `TestGit` banks between `devc pull` and the in-box merge, and relay `main` and the box's `origin/main` stay at the upstream's tip.

**B9: fixed.** A reflink save records every mode that differs from the default in `.devc/savepoints/.modes/<id>` (vault-owned, 0444). The default is an owner-writable, not group/other-writable file, or a 0755 directory. A restore takes modes from that record. Dropping a savepoint removes it. Savepoints made before C07r restore with the old reconstruction. Restores from restic's staging now keep restic's modes exactly, without the extra owner bits. The in-place "unchanged" check compares against the restored mode. Not changed: an in-place restore does not reset the mode of a directory that still exists (it recurses into it); see LEFTOVER. Test: `TestDataReflinkModes` covers 0700/0750/0775 directories and 0600/0664/0444/0755 files, a copy restore, and an in-place restore with a changed mode.

**B13: established, and fixed regardless.** The test was run by hand with a plain container and as the integration test `TestNetworkResolvers` with a devc box. On this host (Podman 5.8.3, slirp4netns) the box user cannot write `/etc/resolv.conf` (owned by container root, 0644). A line added as root in the box (`devc root`) is kept while the container is stopped, but the engine writes the file again at every `podman start` and `podman init`, so the planted resolver did not survive. The exceptions no longer come from that file alone. `netpolicy.TrustedResolvers` takes the host's `/etc/resolv.conf` nameservers. When those are a loopback stub, it adds systemd-resolved's upstream file. It also adds the backend's built-in resolver: slirp4netns's third address (10.0.2.3 by default, or derived from a `cidr=` option), pasta's 169.254.1.1, or a named network's gateways. Only addresses in both that set and the box's file get port-53 exceptions; `up` warns about the rest. Tests: `TestTrustedResolvers`; `TestGather`; `TestInternetLevel`, where a planted 10.66.0.9 gets no exception. Integration: `TestNetworkResolvers` plants a resolver as root and restarts. It checks that the planted address has no exception and that every address that has one is trusted.
